# Global quality rules

- Inspect the existing project and user intent before changing code.
- Prefer a focused change that solves the stated task over a speculative
  rewrite or new dependency.
- Preserve existing behavior, conventions, content, and user-owned files.
- State assumptions and ask when a decision changes product behavior or
  creates meaningful risk.
- Do not fabricate facts, metrics, references, test results, or capabilities.
- Surface failures and unresolved limitations; do not hide them behind
  success-shaped fallbacks.
- Run the smallest relevant checks and report exact outcomes.
